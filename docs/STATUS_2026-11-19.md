# 抖音弹幕助手 · 现状与测试版说明（2026-11-19）

## 1. 已经做到什么

### 采集
- 通过直播间 WebSocket（protobuf / betterproto）接收消息，解析：聊天 `WebcastChatMessage`、表情 `WebcastEmojiChatMessage`、进场 `WebcastMemberMessage`、礼物 `WebcastGiftMessage`、点赞、在线人数、房间统计等。
- 落盘为固定 14 列 CSV（`时间, kind, msg_id, user_id, nickname, fans_club_level, pay_level, content, gift_name, gift_count, diamonds, group_id, visible, session_date`），供归档站点直接消费。
- 另存 `gifts_raw_*.jsonl`、`badge_samples_*.jsonl`、`badge_probe_*.jsonl`（诊断）、`unknown_msgs.jsonl` / `all_msgs.jsonl`（未建模消息留证）、`methods.json`（消息类型计数）。

### 界面（Aurora Dark，1600×1000，左 75% / 右 25%）
- 弹幕行：荣誉等级徽章（48×24）→ 粉丝团灯牌（24×24）→ 星守护（蓝「星」）/ 房管（红「管」）圆标 → **加粗昵称 + 冒号** → 内容；有表情时整行按富文本渲染成图片（文字与表情混排、按字宽换行）。
- 徽章全部为抖音官方素材：荣誉 `new_user_grade_level_v1_<n>.png`（1–75），粉丝团取官方 150×48 长条左端（1–20，11 级以上做色相偏移转橙）。
- 抖音表情：内置 504 个名字 → 图片映射（`assets\dy_emoji\`，532 个文件），`[看]`、`[打脸]`、`[黄脸祈祷]` 等直接渲染成图，图片缺失时退回文字。
- 侧栏：品牌卡、房间/连接控制（连接、断开、导出、登录抖音、清除登录）、4 个指标（当前在线、本场涨粉、付费人数+粉丝团、礼物总额）、礼物面板（固定 8 条铺满，累计 >90 钻才显示，保留最近 200 条，滚轮/拖动回看，无滚动条）。

### 归档与打包
- 按天静态站点（`site_builder.py` / `site_server.py`）：CSV 导出、删除当日、峰值 Top10、跨午夜仍归同一「直播日」，由「导出」按钮生成。
- **下播自动归档 + 自动接下一场**：检测到 `ControlMessage.status == 3`（直播结束）后，先清空窗口里的弹幕 / 礼物 / 指标，再自动导出本场站点、起本地服务并打开浏览器页面；随后回到「等待开播」，冷 20 秒后继续每 5 秒轮询，下一场开播会自动连上。一场只触发一次导出，重连后重置。
- PyInstaller 单文件 exe，资源目录 `assets\ui_badges`（97 张运行时徽章）与 `assets\dy_emoji`（表情包）随包发布。

### 技能
- `douyin-live-danmaku` 技能已发布：<https://github.com/Maple7mi/dsh-skill-douyin-live-danmaku>（含 pitfalls / assets-and-rendering / acceptance），并装到本机 `C:\Users\Administrator\.dsh\skills\douyin-live-danmaku`。

## 2. 今天修掉的三个 bug

| # | 现象 | 根因 | 修法 |
|---|------|------|------|
| 1 | 含表情的两行弹幕，第二行底部笔画被切 | 富文本行高 `_LINE_H = 30`，实际需要 `3 + ascent 26 + descent 7 = 36` | `_LINE_H = 36` |
| 2 | 图标顶边比昵称字顶高一截 | 文字在行框内垂直居中，24px 中文字形顶部比行框低 6px | `badge_box.grid(..., pady=(14, 2))` |
| 3 | 直播间在播却显示「等待开播…」 | `is_room_live()` 兜底抓到页面占位符 `roomId":0` → `0 > 0` 为假 | 只认 SSR `roomStore.roomInfo.room` 对象的 `status`（2/0 在播、4 结束），兜底只认带引号的 roomId，判不出返回 `None` 去尝试连接 |
| 4 | 「礼物总额」比面板里单个礼物还小（截图：总额 234 钻 vs 豆沙包 299 钻） | `_emit_summary()` 限流 0.4s 时**直接丢弃**更新，没有补发 ⇒ 最后一笔礼物永远进不了汇总 | 限流时挂 `threading.Timer` 补发（`_emit_summary_trailing`）；面板新增礼物行时 `_emit_summary(force=True)`；脚注同时显示「共 N 条 · 合计 X 钻」 |

## 3. 测试版是什么逻辑

```
启动
 ├─ _open_logs()          建 logs/gui_<live_id>_<stamp>.csv、gifts_raw、badge_samples、badge_probe
 ├─ _capture_room_meta()  抓主播昵称 / room_id / 标题，供导出站点使用
 └─ 主循环
     ├─ is_room_live()    每 5 秒查一次
     │    status 2/0 → 继续；status 4 → 「等待开播…」继续等；判不出 → 照样尝试连接
     ├─ _connectWebSocket()
     │    取 room_id / ttwid → 建 wss → PushFrame → gzip 解压 → Response
     │    → messages_list 逐条计数、落盘诊断 → 分发到 _parseChatMsg / _parseGiftMsg / ...
     ├─ _handle(kind, data)
     │    更新在线/涨粉/付费人数/礼物总额 → _append() → GUI 行 + _write_csv()
     ├─ 礼物：同一 group 聚合，累计 >90 钻才上屏，只保留 200 条，滚轮回看
     └─ 断线 → 5 秒后重连；跨午夜仍算同一「直播日」
导出 → site_builder 生成按天静态站
```

**测试版与稳定版的隔离**：测试版在 `release\DouyinDanmaku-badge-test\`，自己的 `logs/ site/ cookie.txt`，互斥量带 `BadgeTest` 后缀，可与稳定版同时运行。

## 4. 要达成什么

1. **看得懂的弹幕墙**：谁发的、什么等级、是不是星守护/房管，一眼看清；表情直接显示成图而不是方块。
2. **能长期挂机的数据采集**：按天归档、不丢场次，断线自动重连，跨午夜不断档。
3. **可交付的单文件程序**：双击即用，不需要装 Python；带导出站点能力。
4. **当前这一版的目标**：验证新弹幕区样式（24px 等高图标、加粗昵称、表情内联、礼物 8 条铺满），并等明天开播验证「会员表情」（EmojiChatMessage 里的图片 URL）。
