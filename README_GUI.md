# 弹幕助手 · Aurora Dark 合并版

Windows 桌面弹幕姬：深色 70/30 双栏界面，左侧弹幕/入场混排，右侧状态与高价值礼物。

## 界面

- **整体布局**：左侧约 70% 弹幕区，右侧约 30% 状态区；底部是 Cookie 与采集状态栏。
- **右侧状态区**：
  - 品牌、房间链接、连接/断开/导出按钮、当前在线/累计观看；
  - 2x2 指标：当前在线、本场涨粉、付费人数、礼物总额；
  - 礼物区：18px 单行，最多同时显示 5 条，可滚轮回看。
- **弹幕区**（左侧，占满高度）：
  - 列：消费等级、粉丝团等级、昵称、弹幕内容；正文 18px；
  - 长弹幕自动换行成两行，行高随之增加；
  - 粉丝团灯牌 **> 15 级**的入场会混在弹幕里，用**青色高亮**显示「入场 进入直播间」；
  - 消费等级 **> 35** 或粉丝团 **≥ 15**：金色高亮；
  - 消费等级 **> 40** 或粉丝团 **≥ 18**：红色最高级高亮；
  - 普通弹幕白/浅色交替，双击可复制完整弹幕内容。
- **礼物区**（右侧，最多 5 条可见，可滚轮回看）：
  - 只显示整组累计价值 **> 90 钻（9 元）**的礼物；
  - 每一行格式固定为：
    `小番茄 送出了【跑车】×1 价值1,200钻`
  - 不显示消费等级和粉丝团等级；昵称、礼物名、数量、金额加粗；
  - 连击按 `group_id` 合并为整组数量，不会把 10 连击拆成 10 条；
  - 最新一条在最下方；超过 5 条后可用鼠标滚轮/滚动条回看；同一组礼物数量增加时更新原行并移到末尾；
  - 礼物总额、付费人数统计**全部礼物**（包括 1 钻小礼物），不受 90 钻门槛影响。
  - 抖音的「星守护」「会员」「加入粉丝团」不走普通礼物消息，程序会单独解析成付费事件：
  - 加入粉丝团按 1 钻计入付费人数和礼物总额；
  - 星守护基础价 1280 钻、会员基础价 980 钻；如果消息文案里有「1980钻」「3个月」这类信息，会优先按文案计算；
  - 文案没有价格/时长时才用基础价估算，并在记录里保留原始文案。
- 界面不显示时间戳；**导出的 CSV / 按日网站仍保留完整时间戳**。
- 未开播时显示「等待开播…」，每 5 秒检测一次；检测到开播后自动连接，不会把上次下播的在线人数当成实时数据。

## 启动

```powershell
cd D:\DsProjects\DouyinLiveWebFetcher
.\.venv\Scripts\python.exe aurora_gui.py
```

首次使用需要装依赖（已装过可跳过）：

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

把直播间链接（如 `https://live.douyin.com/617650815017`）粘贴到顶部输入框，点「连接」。

默认窗口为 1600×1000，适合平板/大屏观看；也可以拖动窗口边缘放大。

## 礼物必须填 Cookie

抖音现在只向**已登录账号**推送礼物消息；游客身份只能收到弹幕、进场、在线人数等，礼物区会一直是空的。这是平台限制，不是程序漏抓。

获取方式：

1. 用 Chrome / Edge 打开 `https://live.douyin.com/`，确认已经登录；
2. 打开开发者工具：按 `Ctrl+Shift+I`，或右键页面 →「检查 / Inspect」，或浏览器菜单 →「更多工具」→「开发者工具」；
3. 点 `Network`（网络）→ 筛选 `Fetch/XHR` → 刷新页面；
4. 点一条发往 `live.douyin.com` 的请求 → `Headers` → `Request Headers` → 找到 `Cookie:`，复制整行值；
5. 把整行值粘贴到程序顶部的 **Cookie** 输入框，点 **保存**；或保存为项目目录下的 `cookie.txt`（程序启动时自动读取）。

`cookie.txt` 已加入 `.gitignore`，不会被提交。Cookie 等同于登录凭证，不要发给别人、不要截图外传；建议用一个只用于看直播的小号。

**不填 Cookie 也能用**：弹幕、入场、在线人数、涨粉、累计观看都正常，只有礼物相关统计为空。

## 输出文件

连接后自动在 `logs/` 下生成：

- `gui_<直播间>_<时间>.csv`：所有弹幕、>15 级入场、所有礼物（含未达到 90 钻展示门槛的）；开通「星守护 / 会员」也会作为付费礼物记录。
- `gifts_raw_<直播间>_<时间>.jsonl`：所有原始礼物消息，便于核对连击数量。

CSV 表头：

```text
received_at,kind,msg_id,user_id,nickname,fans_club_level,pay_level,content,gift_name,gift_count,diamonds,group_id,visible,session_date
```

`session_date` 是**直播日**：以开播当天为准，跨午夜的部分仍归到开播当天。

## 导出按天网站

点顶部 **「导出网站」** 可立即生成；程序运行期间也会自动维护站点。它读取 `logs/` 里所有 CSV/JSONL，生成按直播间分开的目录：

```text
site_617650815017/
  index.html              所有日期入口
  2026-11-17.html         每天一页（全部消息 + 当日礼物榜）
  assets/style.css
  manifest.json
```

- **自动更新**：程序运行期间每 2 分钟检查一次，有新内容就重新生成；关闭程序时再更新一次。**按直播日归档**：一场从晚上开播、跨到第二天凌晨的直播，仍归在开播当天，不会拆成两页。
- 网站最上面固定显示「抖音弹幕归档」；主播名、房间号放在每张日期卡片和日期页顶部。
- 每天一页，按采集时间升序；支持按「全部 / 弹幕 / 礼物 / 入场」筛选和关键词搜索。
- 日期页顶部显示**主播名、房间号、直播阶段时间范围**，礼物榜顶部显示**当日总额、付费人数**，同一天多场直播会合并统计。
- 日期页有「导出当日 CSV」「删除当日」，首页有「导出全部 CSV」。
- **删除当日**会从归档中移除该日（原始 `logs/` 保留），只在从程序里点「导出网站」打开的页面可用；直接双击 HTML 时没有本地删除服务，会提示从程序打开。
- 当日礼物榜按 **用户 ID** 汇总当天全部礼物（包含 1 钻小礼物）；连击按整组合并。
- 纯静态页面，双击 `site_<直播间>/index.html` 即可查看；但「删除当日」需要程序启动的本地服务。
- 命令行也可以单独生成：`python site_builder.py --logs logs --out site_617650815017 --live-id 617650815017`
- 想先看样式：打开 `site_preview/index.html`（模拟数据）。

## 口径说明

- **涨粉**：从程序连接那一刻开始，用主播粉丝数的首次值做基线；连接前的涨粉不算。界面已标注「自连接时起算」。
- **付费人数**：按发送过礼物（任意金额）的用户 ID 去重；不含只发弹幕的用户。
- **礼物总额**：所有礼物按「服务端单价 × 实际数量」累计；连击取整组增量，避免重复累加。
- **当前在线**：`RoomUserSeq.total` / 房间统计消息里的在线人数；抖音可能抽样，不保证与 App 完全一致。
- **累计观看**：`total_pv_for_anchor`，主播侧累计观看人次。

## 已知限制

- 只能采集**连接之后**的实时弹幕，拿不到连接前的历史；断线会自动重连，但重连期间的弹幕会丢失。
- 抖音 Web 端可能限流/抽样，不能保证 100% 全量；高流量房间更明显。
- 礼物依赖登录 Cookie；`>90 钻`礼物和 `>15`级入场需要真实样本验证，测试房间不一定每场都有。
- 仅供个人复盘、研究使用；不要传播他人弹幕/个人信息，不要商用。
